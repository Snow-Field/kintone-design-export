# Excel出力

## 判断履歴

### D-07 2026-08-21 配色をテーマ定義1か所に集約する

- 背景 / 問題: 利用者が後日自分で色を調整する前提（P-03）だが、現状は色がスタイル定数と各所に散在している。
- 決定と理由: 色・フォントを専用のテーマ定義に集め、そこだけを差し替えれば全シートに反映される構造にする。利用者が触る対象を1ファイルに限定するため。
- 補足: 初期値はコントラスト比を検証した濃紺系とする（P-04）。値の根拠は仕様側に記載する。

### D-06 2026-08-21 ライブラリ移行と設計刷新を2段階に分ける

- 背景 / 問題: ライブラリ交換と出力仕様の変更を同時に行うと、不具合が出たときに原因がどちらにあるか切り分けられない。
- 検討した選択肢: (a) 一括で行う (b) 交換と刷新を分ける。
- 決定と理由: (b) を採用。先に出力内容を変えずライブラリだけを差し替え、既存のスナップショットテストで等価性を確認する。土台の正しさを保証してから仕様変更に進めるため。
- 却下した理由: (a) は総工数が少ないが、スナップショットが全面的に作り直しになり回帰検出の手段を同時に失う。

### D-05 2026-08-21 自動計算情報シートを廃止する

- 背景 / 問題: フィールドシートの属性を専用列へ展開すると（D-03）計算式が独立した列になり、自動計算情報シートと内容が重複する。
- 決定と理由: 廃止する。オートフィルタで計算式列を絞り込めば同じ一覧が得られるため、シートを維持する利点がない。
- 却下した理由: 「式の棚卸し用に残す」案もあったが、フィルタで代替できる重複を残すと二重管理になる。

### D-04 2026-08-21 API の値を日本語に変換せず出力する

- 背景 / 問題: `SINGLE_LINE_TEXT` や `AFTER` といった値がそのまま出力されており、日本語化するか選択が必要だった。
- 検討した選択肢: (a) 日本語へ変換 (b) API の値のまま (c) 併記。
- 決定と理由: (b) を採用。変換表を持たないため kintone 側でフィールド型が追加されても追従不要で、API を直接扱う読み手にとっても正確。
- 却下した理由: (a) は約30種のフィールド型の変換表を保守し続ける必要がある。(c) はセルが冗長になり、未知の型で表記が崩れる。

### D-03 2026-08-21 フィールドの属性を専用列に展開する

- 背景 / 問題: フィールドシートの「仕様」列に、型ごとに意味の異なる13種類の属性が `key=value` 形式で詰め込まれ、人が読める形になっていなかった。
- 検討した選択肢: (a) 全属性を専用列へ (b) 属性名と値の子行に展開 (c) 主要な属性のみ列に昇格。
- 決定と理由: (a) を採用。1フィールド=1行が保たれ、一覧性とフィルタ適用の両立ができる。
- 却下した理由: (b) は列は増えないがフィールド一覧としての俯瞰性を失う。
- 補足: 値が複数ある属性（選択肢・対象ユーザー）は列内でカンマ区切りとする。行展開すると1フィールド=1行が崩れるため、D-02 とは扱いを分ける。

### D-02 2026-08-21 紐づけ情報を行方向に展開する

- 背景 / 問題: ルックアップの「ほかのフィールドのコピー」やアクションの「フィールドの関連付け」が `A->B,C->D` の形で1セルに詰め込まれ、対応関係が読み取れなかった。
- 検討した選択肢: (a) 1マッピング=1行に展開して専用列に分ける (b) セル内改行 (c) 親子形式のインデント。
- 決定と理由: (a) を採用。コピー元とコピー先が独立した列になるためフィルタと並び替えが効き、列幅も安定する。
- 却下した理由: (b) と (c) は1セルに複数の情報が残るため、検索と絞り込みが効かない。

### D-01 2026-08-21 Excel出力ライブラリに ExcelJS を採用する

- 背景 / 問題: 見出し行の固定とオートフィルタが必要（P-01）だが、現行の xlsx-js-style は見出し固定に対応せず、4年間更新が止まっている（P-05）。
- 検討した選択肢: (a) ExcelJS (b) write-excel-file (c) xlsx-js-style を継続。
- 決定と理由: (a) を採用。P-01 の2機能を両方満たす唯一の選択肢であり（P-07）、ブラウザ向けビルドが同梱されているため拡張機能の実行環境でも追加の polyfill を必要としない。バンドルサイズも現行とほぼ同等。
- 却下した理由: (b) はメンテナンスが最も活発だがオートフィルタに非対応（P-06）。(c) は移行コストが無いが見出し固定を実現できず、メンテナンス終了の依存を抱え続ける。
- 補足: 当初は (b) を推奨としていたが、オートフィルタ非対応を型定義で確認して覆した。ExcelJS 自体も更新頻度は高くない（最終 2024-12）ため、将来の乗り換え余地を残す目的で出力層をスタイル定義から分離する。
