## シート構成

| # | シート | 内容 |
| --- | --- | --- |
| 1 | 一般情報 | ドメイン・アプリ名・アプリID・説明 |
| 2 | フィールド | 全フィールドの属性一覧 |
| 3 | アクション情報 | アクションの設定とフィールドの関連付け |
| 4 | ルックアップ情報 | ルックアップの設定とフィールドのコピー元・コピー先 |
| 5 | 関連レコード情報 | 関連レコード一覧の設定と表示フィールド |
| 6 | 一覧 | 一覧の設定と表示フィールド |
| 7 | アプリのアクセス権 | ユーザー・グループ・組織ごとの権限 |
| 8 | レコードのアクセス権 | 条件ごとの権限 |
| 9 | フィールドのアクセス権 | フィールドごとの権限 |
| 10 | プロセス管理 | ステータスと作業者、アクションと遷移条件 |

シートの並び順は上表のとおり。

## 共通の体裁

- 表は A1 から始める。余白の行や列は設けない。
- 1つのシートに表が複数ある場合（プロセス管理）は、1列空けて横に並べる。縦に積むと列幅が表どうしで共有され、片方の長い値がもう片方の列を広げてしまうため。
- 見出し行を固定する。2段見出しのシートは2行とも固定する。
- 表が1つだけのシートには見出し行にオートフィルタを設定する。Excel の仕様上シートあたり1つまでのため、表が複数あるシートには設定しない。
- 列幅は見出しと値の表示幅から算出する。折り返し表示は使わない。日本語フォントの全角文字は標準文字幅の2倍よりわずかに広いため、その差と見出しの太字ぶん、およびオートフィルタのボタンぶんを見込む。
- 算出した列幅は上限と下限の範囲に収める。値は配色と同じ定義ファイルに全列共通で持ち（上限 50・下限 6）、必要な列だけ個別の上限で上書きする。上限を超える値はセルの端で切れる。
- 偶数行に薄い背景色を敷く。
- 設定の有効・無効は `■`（有効）と `□`（無効）で表し、`■` のセルには背景色を付ける。
- 行の種類（フィールドの型、アクションの種類など）にそもそも存在しない項目は `-`、存在するが未設定の項目は空欄とする。

## 配色

色とフォントの定義は1か所に集約し、そこを差し替えれば全シートに反映される。

| 用途 | 色 | 文字色 | コントラスト比 | 判定 |
| --- | --- | --- | --- | --- |
| 上段見出し | `#1F3864` | `#FFFFFF` | 11.6:1 | WCAG AAA |
| 下段見出し | `#2F5597` | `#FFFFFF` | 7.3:1 | WCAG AAA |
| 偶数行の背景 | `#F2F7FC` | 既定（黒） | — | — |
| 有効（`■`）のセルの背景 | `#C6E0B4` | 既定（黒） | 14.7:1 | WCAG AAA |
| 罫線 | `#BFCBD9` | — | — | — |

フォントは Yu Gothic UI。

色を変更する場合もコントラスト比 4.5:1（WCAG AA）以上を維持する。

## フィールドシートの列構成

上段の見出しでグループ化し、下段に個々の列を置く。

| グループ | 列 |
| --- | --- |
| 基本 | No.／フィールドコード／フィールド名／タイプ／テーブル／グループ |
| 入力制約 | 必須／重複禁止／最大長／最小長／最大値／最小値 |
| 初期値・選択肢 | デフォルト値／選択肢／選択肢の並び／対象ユーザー |
| 計算・表示形式 | 計算式／計算式の表示／表示形式／小数桁／単位／単位の位置／桁区切り |
| 表示 | ラベル表示／リンク種別／サムネイルサイズ／グループ初期表示／機能の有効 |

1フィールドを1行で表す。サブテーブル内のフィールドも行として出力し、「テーブル」列に明細名を入れる。グループとサブテーブルはそれ自体の見出し行も出力する。

入力制約より右の属性列は、そのフィールドの型に属性が存在しなければ `-` とする（例: 数値フィールドの「最大長」）。ラベル・スペース・罫線・グループ・サブテーブルの行は、属性列をすべて `-` とする。

## 1設定1行

1つの設定を1行で表す。複数の値は列の中でカンマ区切りにし、組になる値は `元 → 先` と書く。

| シート | 1行の単位 | 1セルにまとめる値 |
| --- | --- | --- |
| 一覧 | 一覧 | 表示するフィールド（一覧形式以外は `-`） |
| ルックアップ情報 | ルックアップフィールド | ほかのフィールドのコピー（`コピー元 → コピー先`）、コピー元のレコードの選択時に表示するフィールド（別の列） |
| 関連レコード情報 | 関連レコードフィールド | 表示するフィールド |
| アクション情報 | アクション | フィールドの関連付け（`コピー元 → コピー先`。レコード URL は `RECORD_URL → コピー先`）、実行できる利用者 |
| プロセス管理 | ステータス／アクション | 作業者、実行できるユーザー |

レコードのアクセス権とフィールドのアクセス権は、対象ごとに権限が異なるため1行1対象とする。アプリのアクセス権はもともと1行1対象である。

## プロセス管理シートの列構成

ステータスの表とアクションの表を、1列空けて横に並べる。

| 表 | 列 |
| --- | --- |
| ステータス | No.／ステータス名／作業者の指定方法／作業者 |
| アクション | 実行前／アクション名／実行後／種類／実行できるユーザー／条件 |

- ステータスは No. 順に1行1ステータスで出力する。
- アクションは実行前ステータスの No. 順に並べ、同じステータス内では kintone の設定順を保つ。分岐の2つ目以降（`SECONDARY`）だけが実行できるユーザーを持つため、`PRIMARY` の行は `-` とする。

## 値の表記

kintone REST API が返す値をそのまま出力し、日本語へ変換しない。フィールド型（`SINGLE_LINE_TEXT` など）、エンティティ種別（`USER` / `GROUP` / `ORGANIZATION`）、単位の位置（`BEFORE` / `AFTER`）、作業者の指定方式（`ONE` / `ALL` / `ANY`）、アクションの種類（`PRIMARY` / `SECONDARY`）が該当する。

ユーザー・グループ・組織などをカンマ区切りで並べる列では、各値を `種類:コード` と書く（例: `GROUP:sales, USER:user1`）。コードを持たない作成者は `CREATOR` とだけ書く。下位組織にも適用する場合は末尾に `(下位含む)` を添える。
